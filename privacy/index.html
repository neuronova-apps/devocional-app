Privacidad · Mi Momento

Política de privacidad

Esta política describe el comportamiento real de la demo web actual: qué registros personales y acciones devocionales se guardan en el navegador, cómo se validan y qué elementos de muestra no se persisten.

Responsable

Mi Momento forma parte de Neuronova Apps, iniciativa personal e independiente desarrollada por Gabriel Berrospi.

02

Alcance actual

Esta política corresponde a la demo web funcional publicada en GitHub Pages. Actualmente permite guardar oraciones, reflexiones y progreso devocional local generado por acciones realizadas en la propia demo.

La biblioteca continúa siendo limitada: cada plan muestra una duración conceptual mayor, pero la versión actual solo publica tres sesiones completables por plan. Las notas de seguimiento de oraciones, cuentas, sincronización, copias de seguridad y otras funciones siguen sin implementarse.

03

Datos y almacenamiento local

La demo puede utilizarse sin crear una cuenta y sin proporcionar nombre, correo electrónico, teléfono u otros datos identificativos.

Mi Momento utiliza localStorage con la clave mimomento-local-v1. El objeto guardado declara version: 1 y puede contener prayers, journal y devotional.

En una oración pueden conservarse ID local, título, texto, categoría, fecha visible, estado activa/respondida y fecha técnica de creación. En una reflexión pueden conservarse ID local, fecha visible, texto y fecha técnica de creación.

Estos datos se procesan en el navegador y no se envían a una base de datos propia de Mi Momento en la configuración actual.

04

Progreso devocional

El bloque devotional guarda únicamente registros de acciones completadas. Para el devocional diario se conserva la fecha local de finalización y una marca temporal técnica. Para los planes se conserva la sesión completada —actualmente de 1 a 3—, su fecha local y una marca temporal técnica.

La racha, el porcentaje de avance, el total de sesiones y el calendario de los últimos 28 días no se guardan como cifras independientes. Se recalculan en el navegador a partir de los registros de finalización válidos.

El porcentaje global de planes usa únicamente las doce sesiones actualmente disponibles: tres por cada uno de los cuatro planes. Los días conceptuales que todavía no tienen contenido no se cuentan como progreso.

05

Validación, recuperación y migración

Antes de utilizar datos restaurados, la aplicación comprueba la versión del formato y valida cada registro. Los IDs inválidos o duplicados se descartan; los textos se normalizan y limitan; las categorías y estados desconocidos se sustituyen por valores seguros.

Las fechas de actividad devocional deben corresponder a un formato válido YYYY-MM-DD. Solo se acepta una finalización diaria por fecha y las sesiones de plan se normalizan a una secuencia continua desde la sesión 1, sin saltos.

Los estados anteriores de mimomento-local-v1 que no contienen el bloque devotional siguen siendo compatibles: se cargan con progreso vacío y se normalizan al nuevo formato ampliado.

Si el JSON almacenado no puede leerse, la aplicación intenta recuperar registros personales válidos desde las claves heredadas devotionalPrayers y devotionalJournal. Si la migración se guarda correctamente, esas claves antiguas se eliminan.

Si se encuentra una versión futura que esta demo no entiende, no se sobrescribe ese formato. Si el navegador bloquea localStorage, la demo continúa temporalmente en memoria durante la sesión.

06

Datos y contenido de demostración

La interfaz incluye oraciones y reflexiones precargadas para mostrar el diseño. Esos ejemplos se mantienen en el código y no se serializan en localStorage.

La biblioteca devocional también sigue siendo contenido de muestra. Sin embargo, cuando la persona marca el devocional diario o una de las tres sesiones disponibles de un plan como completada, esa acción sí se registra como progreso local real.

Los ejemplos de oración y diario no participan en contadores personales y no pueden modificarse como registros propios.

07

Uso de la información

Los registros locales se utilizan para volver a mostrar oraciones y reflexiones personales, mantener el estado activa/respondida y reconstruir el progreso devocional de la demo.

Mi Momento no utiliza actualmente esos textos o registros de progreso para publicidad personalizada, elaboración de perfiles comerciales ni venta de datos.

08

Seguridad y límites del almacenamiento local

localStorage mantiene los datos dentro del perfil del navegador, pero no constituye por sí mismo cifrado de extremo a extremo ni una bóveda protegida por contraseña. Una persona con acceso al mismo dispositivo, perfil del navegador o herramientas de desarrollo podría acceder a los datos del sitio.

Por tratarse de textos potencialmente íntimos, se recomienda no utilizar la demo para información que requiera un nivel de protección superior al almacenamiento local del navegador.

09

Retención y eliminación

La demo actual todavía no ofrece controles de edición o eliminación individual para oraciones, entradas del diario o eventos de progreso devocional. Los datos guardados permanecen en localStorage hasta que el navegador los elimine o la persona borre los datos del sitio desde la configuración del navegador.

No existe una cuenta de usuario ni una base de datos remota de Mi Momento que requiera una solicitud separada de eliminación.

10

Servicios de terceros

La versión web se publica mediante GitHub Pages y utiliza recursos compartidos del ecosistema Neuronova Apps. No utiliza actualmente servicios publicitarios ni un SDK propio de analítica para las funciones principales descritas en esta política.

Los enlaces externos se rigen por las políticas del servicio de destino.

11

Funciones futuras y publicación móvil

Antes de incorporar cuentas, sincronización, copias de seguridad, recordatorios remotos, analítica, publicidad, SDK externos o una versión móvil distribuida mediante una tienda, se revisarán el tratamiento de datos, permisos, bibliotecas y declaraciones públicas aplicables.

Las declaraciones de seguridad de datos de cualquier tienda deberán corresponder al funcionamiento real de la versión publicada, no a funciones previstas.
